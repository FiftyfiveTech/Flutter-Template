Q1
Why split the PRD into one file per feature (Step 2) before designing any screens?
⌄

☐ It is required by Flutter's build system.

☑ It gives every screen a clear feature name to be tagged with, so later you can just say "build the onboarding flow" and everyone knows what that means.

☐ It automatically generates the Firestore schema.

Q2
Why run the audit and layout-check skills at the end of every feature in Step 7, instead of once at the end of the whole project?
⌄

☐ Skills can only be used once per project.

☑ Catching a mistake right after you build a feature is much cheaper than finding it several features later, once other code already depends on it.

☐ It has no effect on cost or quality — it's purely a style preference.

Q3
What's the difference between what graphify (Step 8) gives you and what a decision log gives you?
⌄

☐ They are the same thing — only one is needed.

☑ Graphify tells you how the code is connected. A decision log tells you what you decided and why, across sessions. A long project needs both.

☐ Graphify replaces the need for architecture docs entirely.
