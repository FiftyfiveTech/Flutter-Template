Quick reminders pulled straight from the real problems on the Challenges page — keep these in mind while you work.

✅ Do❌ Don't
Check both the PRD and the design mockups when they disagree, and write down which one you followed and why. Assume one of them is automatically right and ignore the other.
Use a checklist when you change your database structure — one column change can touch the table, the repository, and the datasource. Trust yourself to remember every file a schema change needs to be updated in.
Review generated code file changes (like .g.dart) before you commit them. Blindly stage and commit every file, generated ones included, without checking what changed.
Write down real-device testing quirks (odd file paths, screenshot sizes, key presses) the first time you hit one. Assume a real phone or tablet will behave exactly like the simulator/emulator.
Keep a simple, written log of important decisions as the project goes on. Rely on memory — yours or a teammate's — to recall why a decision was made weeks later.
Update CLAUDE.md and your skills whenever a new rule or edge case comes up. Treat CLAUDE.md as a one-time setup file you write once and never open again.
