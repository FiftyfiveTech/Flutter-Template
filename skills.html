Bundled with this template

SkillPurpose
flutter-feature-scaffoldGenerates the Clean Architecture boilerplate (entity, repo interface, use case, controller, DTO, datasource, repo impl) for a new feature.
api-data-syncWires Firestore remote datasources, Drift local DAOs, and the offline sync queue consistently.
riverpod-state-managementProviders/controllers/notifiers, async loading/error state, test overrides.
flutter-ui-design-systemKeeps widgets on design tokens; catches hardcoded color/spacing/type.
flutter-overflow-auditKeyboard-open / RenderFlex overflow checks for forms, sheets, modals.
flutter-testingUnit/repository/widget/golden tests matched to the layer being tested.
CommandPurpose
/new-feature <name>Scaffolds folders and .gitkeep files for a new Clean Architecture feature.
/create-screen <name>Generates a screen page using theme tokens.
/create-provider <name>Scaffolds a Riverpod controller/notifier.
/create-model <name>Scaffolds an immutable data model.
/connect-api <name>Wires a feature's remote datasource to REST (Dio) or Firestore.
/generate-tests <target>Generates tests for a given class/file, matching its architectural layer.
/refactor-widget <target>Extracts or promotes a widget, applying the shared-vs-feature-local boundary rule.
/review-codeReviews a diff/file against this project's architecture rules.
/dod-checkPerforms a Definition of Done audit.
/audit-architectureRuns a repo-wide architecture/compliance audit.

General-purpose, worth adding to any AI-assisted Flutter project

SkillWhy it earns a slot
security-reviewPre-merge pass for injection/secrets/OWASP-class issues — cheap insurance on any app handling user data.
code-review / simplifyIndependent second pass for correctness and over-engineering before merging a flow.
datavizIf the product has any charts/progress graphs, gives consistent, accessible chart styling instead of ad hoc plotting choices.
a11y-compliance (build this one)Screen-reader labels, contrast, touch-target size — not covered by the overflow-audit skill, which is layout-only.
performance-audit (build this one)const-constructor discipline, rebuild-tree checks, memory leaks — worth adding once the app has enough screens that jank becomes possible.
l10n (build this one, if multi-language is planned)Standardizes ARB-based localization instead of ad hoc string tables.
fewer-permission-promptsRun once the workflow stabilizes — pre-allowlists the read-only commands you approve every time anyway.
loopUseful for making Step 8's graphify re-check actually recurring instead of manual.
Domain-specific compliance skill (build this one if applicable)If your product has a regulated or safety-critical domain, bake its rules into a skill rather than relying on remembering to ask for them every time.

Adding a new skill — create .claude/skills/[skill-name]/SKILL.md as a checklist for the AI coding assistant to verify before finishing feature work, with trigger phrases to fire automatically. Update CLAUDE.md's skills section every time one is added.
