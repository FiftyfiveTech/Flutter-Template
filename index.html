05 / Installation

Get started in minutes.

STEP 01

Clone the template

Clone this repository (or use it as a template) and open the project root in your editor.

git clone <repo-url> your_app
STEP 02

Generate platforms

Generate Android, iOS, Web, and other platform runners around the existing Flutter source.

flutter create .
STEP 03

Rename the package

Replace the default package name and update platform application identifiers.

flutter_app_template → your_app
STEP 04

Install dependencies

Fetch all Flutter and Dart dependencies from the project root.

flutter pub get
STEP 05

Generate code

Generate Drift database and Riverpod notifier source files.

dart run build_runner build --delete-conflicting-outputs
STEP 06

Configure Firebase

Only required when using the Firestore datasource.

flutterfire configure
STEP 07

Run the app

Launch the application using Flutter's standard development runner.

flutter run
06 / Infrastructure

Swap your backend without rewriting your app.

REST / Dio

Dio Client Datasource

Handles standard JSON communication with REST endpoints through a reusable HTTP client.

Firebase

Cloud Firestore Datasource

Provides direct Firestore collection access while keeping backend details outside the domain.

counter_controller.dart 
@riverpod
CounterRemoteDatasource counterRemoteDatasource(
  Ref ref,
) {
  // REST / Dio
  return CounterRestDatasource(
    ref.watch(baseApiClientProvider),
  );

  // Firebase / Firestore
  // return CounterFirebaseDatasource(
  //   FirebaseFirestore.instance,
  // );
}
✓

No domain changes required. Entities, repository contracts, and UI pages remain completely independent of the selected backend.

07 / Data

Choose your synchronization strategy.

A

Direct Remote

Writes directly to the server and updates the local cache after a successful response. Recommended for standard CRUD applications.

B

Offline-Only

Stores data exclusively in local SQLite/Drift. Useful when remote synchronization is not required.

C

Outbox Sync

Writes immediately to local Drift, updates the UI optimistically, queues a synchronization task, and processes it in the background when connectivity returns.
